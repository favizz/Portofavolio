Docker — Multi-Service Architecture Showcase

Why a walkthrough and not a live demo: Docker is a packaging/orchestration tool, not something that runs "in the browser" — Vercel doesn't host containers at all. This page presents a real, six-service docker-compose.yml (validated with docker compose config — see the README) for an IoT telemetry platform: the same shape as the Netflow project's own deployment (MQTT broker, Redis-backed job queue, nginx in front of the API), reimplemented here as a small, original, runnable example.

Why it's shaped this way

        
    
          
  • nginx in front of api — the API container is never exposed directly; only nginx's port is published.
    • 
          
  • api never runs detection inline — it only enqueues onto Redis, keeping the MQTT ingest path fast regardless of how slow anomaly detection gets.
    • 
          
  • worker scales horizontally (replicas: 2) — safe with zero coordination code, because Redis's BLPOP hands each queued job to exactly one worker.
    • 
          
  • postgres has a healthcheck; api/worker depend on it via condition: service_healthy — without this, the app containers can start and immediately fail against a Postgres that's still initializing.
    • 
          
  • named volumes for postgres/redis data — docker compose down (without -v) doesn't wipe state on every restart.
