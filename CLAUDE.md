# Portfolio project notes

Astro (static output, no server) + Tailwind CSS v4 (`@tailwindcss/vite`) + GSAP/ScrollTrigger + Lenis smooth scroll. Deploys as plain static HTML/CSS/JS, no backend.

## Content policy

- Never use em dashes anywhere in generated copy or code comments. User preference, see the assistant's own memory system, apply a period/comma/colon instead.
- All personal/CV content must trace back to a real source (`CV_Favian Izza.pdf`, `Transcript_Favian Izza.pdf`, LinkedIn/GitHub, or explicit user instruction). Don't invent tech stacks, numbers, or company facts that aren't stated or aren't verifiable via web search. `dev/FACT.md` is the running source of truth, keep it updated when new real content is added.
- `dev/UPDATE.md` is the user's own scratch file for the next batch of instructions. Never edit it, only read and execute it.
- `dev/TASK.md` lists deliverables only the user can provide (real assets, missing personal facts). Keep it current: remove items once fulfilled, add new ones as they come up.

## Data model (`src/data/`)

Every section reads from a typed data file rather than hardcoding content in the component:
- `projects.ts`, `experience.ts`, `technology.ts`, `certifications.ts`, `education.ts`, `socials.ts`
- Each `projects`/`experience` entry has a `slug`, used as the DOM hook for the expand/carousel interaction and for cross-linking (see below).
- `experience[].tags` are only added when the CV literally names the technology (e.g. Siemens says "Laravel-based", so it gets `['Laravel', 'PHP']`, PHP because Laravel is a PHP framework by definition). Don't add tags based on guessing what stack a role "probably" used.
- `relations.ts` derives cross-links automatically from tag overlap: `findTechRelation(name)` finds the first project (priority) or experience with a matching tag, for making Technology tiles clickable. `findRelatedProject(tags)` finds the best-matching project for an experience entry's tags, used for Career's "see related project" button. If nothing matches, the UI simply doesn't render a link, that's intentional, don't force a fake relation.
- About's stat tiles are computed from `array.length`, not hardcoded numbers. Keep it that way, that's the whole point of it being "dynamic."

## The expand-to-carousel pattern (Projects, Career, Academic)

Shared markup contract per section:
```html
<div data-expand-grid data-expand-section="project|career">
  <div data-expand-carousel></div>
  <div data-expand-stage></div>
  <div class="contents" data-expand-default>
    <article data-expand-card data-slug="...">
      <div class="card-face">...</div>       <!-- shown in grid + stage -->
      <div class="card-detail">...</div>     <!-- shown only in stage -->
      <div class="carousel-face">...</div>   <!-- shown only in carousel -->
      <button data-expand-back data-expand-ignore>...</button>
    </article>
    ...
  </div>
</div>
```
`initExpandableGrids()` in `motion.ts` moves ONLY the selected card into `data-expand-stage` (real `appendChild`); the rest stay hidden in the default slot via CSS. The carousel container holds a STATIC list of `.carousel-item` label buttons (one per slug, rendered in the component, covering every item including the selected one); the active label is highlighted via `data-active`. A FLIP animation (`flipOne()` helper) smooths the card's move into the stage. Visibility of `.card-face` / `.card-detail` / `.carousel-face` is pure CSS keyed off the ancestor (`.expand-stage .card-detail { display: flex }` etc, see `global.css`), not per-card JS classes. Don't duplicate content between `.card-face` and `.card-detail`, if something needs to show only when expanded (like Career's company prestige note), put a low-visibility span inside `.card-face` itself and reveal it via `.expand-stage .role-note { display: inline-block }` rather than repeating the whole block in `.card-detail`.

Project, Career, and Academic all expand into a stage where the card becomes `display: flex; flex-direction: row` with a `.stage-media` column (40% width, capped at 340px, a real image: project screenshot, company logo, or school logo) and `.card-detail` filling the rest (`flex: 1 1 auto`), same rule in all three (see each component's scoped `<style>` block). Since Project/Career/Certification's collapsed hscroll cards also carry a fixed Tailwind width class (`w-[270px] md:w-[340px]`) for the row, and that class stays on the element when it's moved into the stage, `global.css`'s `[data-expand-stage] .expand-card` rule forces `width: 100% !important` to override it, otherwise the expanded card stays pinned at its collapsed width instead of filling the stage. Certification is the one exception: it has no carousel/stage/expand-card interaction at all (see Other conventions below), it only ever renders the collapsed row.

`initExpandableGrids()` also handles pin-only grids: if a `[data-expand-grid]` has `data-hscroll` but no `[data-expand-carousel]`/`[data-expand-stage]` children (Certification), the function still wires up the horizontal scroll pin (`createHscrollPin`, the `fonts.ready`/`load` resettle) and returns before touching any expand/click/label logic.

`data-expand-ignore` on an element (like the back button or the external "Visit site" link) stops its click from also triggering the card's own expand handler.

Cross-section links reuse the same system: any element with `data-open-section="project|career"` + `data-open-slug="..."` fires `initCrossLinks()`, which Lenis-scrolls to that section then dispatches a `portfolio:expand` custom event, which the matching grid picks up and expands. This is how About's highlighted keywords and Technology's clickable tiles jump to and open a specific card.

## Hero wordmark + photo

`Hero.astro` renders a giant low-opacity `FAVIAN` wordmark absolutely centered behind the content (z-index 0, content at z-index 10). The wordmark box has `left`/`right: 2rem` with `overflow: hidden` (instead of a plain centered `left: 50%`) so there is always a deliberate gap between the letters and the viewport edge instead of the text running edge-to-edge. Hero itself is deliberately minimal now: no greeting line, no repeated name/role text, no bio paragraph, no CV button, just the wordmark plus a single centered photo, mirroring nesh's landing (name dominates, face in the middle, nothing else competing for attention). The old bio copy ("I like building things that ship...") moved to `SideNav.astro`'s tagline (see below) instead of being deleted outright, and the CV download moved to `Footer.astro`'s Connect column.

The photo swaps the circular-cropped image for a full-silhouette background-removed cutout (`public/images/profile-cutout.webp`, generated from `profile.jpeg` via a one-off `sharp` raw-pixel white-threshold alpha mask, verified by sampling actual pixel alpha, not just visual inspection), sized as a portrait-ratio box (`h-[26rem] w-64` up to `lg:h-[34rem] lg:w-80`) with `object-contain` so the full body is always visible at every breakpoint and is never cropped/sliced by the container. There's no decorative ring/circle behind it anymore (see Color policy's decoration removal below). `initHeroMorph()` in `motion.ts` owns this photo's `opacity`/`transform`/`filter` completely: a one-time `gsap.from` entrance on load, then an explicit `gsap.fromTo` (not implicit `gsap.to`) scrubbed to Hero's scroll range that lifts, blurs, and fades the photo out as Hero scrolls away. Because this element owns opacity for the whole Hero lifetime, it must never also carry `class="reveal" data-reveal`, if it did, `initReveals()`'s separate fade-in system would race `initHeroMorph()` for the same property and the implicit-`gsap.to` "from" value would get captured mid-race (this exact bug happened once, verify with `getComputedStyle(photo).opacity` sampled at 0/25/50/99% scroll if this area regresses). General rule: no two systems animate the same property on the same element without one of them explicitly owning it.

## Side navigation

The nav is a single persistent element, not the earlier top-header-plus-floating-dots setup: `SideNav.astro` renders a fixed `left-6 lg:left-10 top-1/2 -translate-y-1/2` column (`hidden md:flex`) containing, top to bottom: a short tagline (the bio line moved from Hero), two real dynamic stats (project count, experience count, same `array.length` pattern as About, no fabricated numbers), the section nav links, and a `mailto:` contact email at the bottom, styled after heynesh.com's persistent side rail with its tagline/stats/links/contact stack. There are no social icons in the side nav (removed per instruction, they still exist in `Footer.astro` and the mobile hamburger menu, both unaffected). Active section is highlighted via the same `[data-section]`/`initActiveSection()` wiring the old header dots used. `Header.astro` is mobile-only (`md:hidden` on the whole `<header>`): just the logo plus hamburger toggle, opening the existing fullscreen mobile menu. Because `SideNav` occupies a fixed column at md+, `.section` in `global.css` adds `padding-left: 14rem` (`17rem` at `lg`) starting at the `768px` breakpoint so content never sits underneath it, do not remove that padding without also solving the overlap another way. There is deliberately no idle-hide system (the old `initIdleUI()`/`[data-idle-ui]`/`header[data-idle]` machinery was removed outright in an earlier round): a nav that vanishes after a few seconds of stillness was the exact complaint that drove this redesign, so nothing here should ever be wired back into an auto-hide timer.

The nav also morphs: `initNavMorph()` in `motion.ts` (`gsap.matchMedia`, `md+` only) reads the nav's own resting `getBoundingClientRect()` at init, computes the horizontal offset needed to center it over the viewport, and runs a `gsap.fromTo` scrubbed to Hero's scroll range (`start: 'top top', end: 'bottom top'`, same range as `initHeroMorph`'s photo exit, so both finish together exactly as About appears) from `{ x: <that offset>, opacity: 0, scale: 1.15 }` down to `{ x: 0, opacity: 1, scale: 1 }`. At scroll 0 the nav is fully transparent and visually centered, so the landing page reads as having no side nav at all (an "independent page"); by the time Hero scrolls out it has faded, shrunk, and slid into its resting fixed-left position. This is why SideNav has no logo/brand text of its own, Hero's wordmark + H1-equivalent already declares the name, a third declaration in the nav would be the "double name" the redesign was explicitly asked to remove.

## Section separators

`.section + .section` in `global.css` draws a solid 1px top border (`var(--color-primary-strong)`, not a low-opacity wash) between adjacent sections, a deliberate visual break so each section reads as its own "page" even though the scroll motion itself stays smooth (Lenis) and section backgrounds still cross-fade via the gradient system below. Don't remove this thinking it conflicts with "seamless scroll", the two are orthogonal: motion is seamless, boundaries are visually clear.

## Color policy

The palette is intentionally restricted to black, dark blue, and white, no purple/violet/cyan/magenta. All of it flows from the `@theme` tokens in `global.css` (`--color-bg`, `--color-primary*`, `--color-accent`, `--color-text-muted`), `motion.ts`'s `sectionPalettes` (the per-section gradient-blob colors), and `GradientField.astro`'s default `--blob-*` values, all three must stay in the same dark-blue/near-black family if you touch any of them. Section headings all use the single `text-accent` token now, not per-section rainbow hex values (`text-[#a78bfa]` etc used to vary Achievements/Academic/Technology/Projects/Certifications/Career independently, that was the "gradient" look the user explicitly asked to remove), including About's heading which used to be the one straggler on `text-primary-strong` (a dark blue close to the near-black background, a real low-contrast bug, not just an inconsistency).

Decorative background flourishes were stripped out entirely, they were adding visual noise without conveying information: `GradientField.astro`'s twinkling `.stars` layer is gone (the blobs + grain noise stay, that's the intentional background system), Hero's blur-circle/dashed-ring behind the photo is gone, About's rotated-square/white-ring frame around the profile photo is gone, and each section's ambient SVG decoration is gone (About's `.nebula` radial gradient, Career's `.flight-path` dashed line, Projects' `.constellation` lines, Technology's `.orbit-rings` dashed circles). Don't add a new one of these per-section "ambient" decorations without a specific reason, the whole category was a deliberate removal, not an oversight.

The `.glow-border` class (border + accent box-shadow on hover) was renamed to `.hover-border` and the box-shadow dropped, it's a plain border-color hover transition now. Same for `.btn-interactive`'s hover/active states, the box-shadows are gone, only the transform lift/press remains. The expanded-card border glow (`[data-expand-stage] .expand-card`'s box-shadow) is gone too. If you're tempted to add a glow/shadow-based hover effect anywhere, don't, that's the exact effect that was removed.

Technology's section used to be the only one centered (`items-center text-center`) while every other section is left-aligned, that inconsistency is fixed, Technology now matches the rest (`items-start text-left`).

## Scroll-lock

`initScrollLock()` finds whichever section currently covers the most viewport area, and if that section's `h1`/`h2` sits between 40% and 60% of viewport height, waits 1s of continued stillness then Lenis-snaps to it. Guards against fighting its own triggered scroll via an `isSnapping` flag. If this ever feels too aggressive, the fix is tuning the 40-60% band or the 1000ms delay, not ripping the feature out.

## Other conventions

- Directional/navigation actions use `.text-cta` (highlighted text + arrow, e.g. "Visit site →", "← Return"), not boxed buttons. Boxed buttons are reserved for primary CTAs (CV, form submit). The CV download button lives in `Footer.astro`'s Connect column (moved out of Hero, which is text-free now).
- Certification does not expand. `Certifications.astro`'s cards are plain, non-interactive (`article`, no `data-expand-card`/`role="button"`/click handler) with a real `.text-cta` "View document" link straight to the certificate's document (`certifications.ts`'s `documentUrl` field, real Google Drive links for the three real certs sourced from `dev/FACT.md`'s verified CV hyperlink file IDs, `https://google.com` placeholder for the two `dummy: true` carousel-filler entries). It still keeps its `data-hscroll` pinned horizontal scroll (still nice for browsing many certs), just no click-to-expand-into-stage behavior, see the expand-to-carousel section above for how `initExpandableGrids()` supports this pin-only mode.
- Contact is a form (Name/Email/Subject/Message) whose submit opens a prefilled Gmail compose window (`https://mail.google.com/mail/?view=cm...`) addressed to the user. No backend, nothing stored; keep it that way unless the user picks a form service.
- Projects/Certification/Career grids carry `data-hscroll`: collapsed state is a row of fixed-width nesh-style cards translated horizontally by vertical scroll. This lives inside `initExpandableGrids()` in `motion.ts` (not a separate function), via `createHscrollPin()`/`destroyHscrollPin()`: the section is GSAP-`pin: true`'d for the duration of the row's translateX, so the page cannot scroll past a still-animating carousel, it visually "finishes" the row before releasing the pin. The pin lifecycle is coordinated with expand/collapse: `expand(slug)` calls `destroyHscrollPin()` before the FLIP transition (the row layout changes entirely once a card is staged), `collapse()` rebuilds it via `createHscrollPin()` on the next two animation frames. Academic stays a numbered row list (`data-list`, no pin).
- Dummy carousel-filler entries in `projects.ts`/`certifications.ts` have `dummy: true` and are excluded from About's stats. Never let dummies leak into stats or FACT.md.
- The horizontal carousel's scrub is a pure function of absolute scroll position (GSAP `scrub: true`), so landing directly on a mid-scrolled section (hash link, refresh) already shows the correct offset with no "first visit" replay needed. Because web-font swap and late image loads can shift section heights and stale the trigger measurements taken at init, the hscroll setup re-runs via a `resettle()` (`destroyHscrollPin()` + `createHscrollPin()`) on `document.fonts.ready` and `window load` as a safety net, don't remove that.
- The vertical carousel (expanded-state label list) changes selection on `wheel` over the carousel itself, not just click, mirroring the horizontal carousel's scroll-driven feel. See the `wheel` listener in `initExpandableGrids()`. Touch devices never fire `wheel`, so there's a second, parallel `scroll` listener on the same carousel that watches native `scrollTop` (the list already has `overflow-y: auto`) and snaps to whichever label sits nearest the container's center, this is what makes the carousel usable on mobile. The two never conflict: the wheel handler's `preventDefault` keeps `scrollTop` from moving at all on desktop. The expanded layout itself (`[data-expand-grid][data-expanded]`) stacks carousel-above-stage in a column below the `768px` breakpoint and only switches to the row layout at `md+`, a fixed-width side-by-side row on a narrow phone screen was the other half of "vertical carousel doesn't work on mobile."
- Pinned hscroll sections rely on `ScrollTrigger.config({ ignoreMobileResize: true })` (set once, near `gsap.registerPlugin`). Mobile browsers fire a `resize` event when the address bar collapses/expands mid-scroll, without this flag ScrollTrigger treats that as a real viewport change and re-measures the pin mid-transition, which is why the horizontal carousel used to fall short of the end of the row on phones. Don't remove this to "fix" an unrelated resize bug without checking mobile hscroll first.
- Back buttons in expanded cards are icon-only (`.back-arrow-icon`, a CSS `mask-image` using `public/images/icons/back-arrow.webp` recolored via `background-color: currentColor`), no "Return" text.
- Programmatic scrolls must go through `scrollProgrammatic()` in motion.ts, which suppresses the scroll-lock while the tween is in flight. Cross-links scroll to the target `[data-expand-grid]` (the content), not the section heading.
- Browser-testing note: Lenis animates on requestAnimationFrame, which Chrome pauses in backgrounded tabs, so automated scroll verification in a background tab will appear frozen. Verify scroll targets by instrumenting `lenis.scrollTo` calls instead.
